The one-linerWhat pre-processing is

When a customer uploads a site-plan PDF, a cloud job splits it into per-sheet images and PDFs, then Google Gemini reads every sheet — naming it, summarizing it, boxing its content, and transcribing its tables and notes into Postgres so the app and the review pipeline can navigate the drawing as structured, searchable data.

The problemThe transcriptions can't be trusted

The AI reading layer is wrong at a rate that makes it dangerous as the source of any number, name, or symbol — and the defects are invisible to every existing check, because row counts, headers, and structure survive intact while the cell contents rot.

measured on the benchmark package ~40 of 57 sheets on the 1700 S. Lamar run carry at least one recorded transcription defect. Sheet 04 has no transcription at all — so every "search all sheets" text sweep silently covered 56 of 57. The 08-04 run and FTL's Take 5 logged the same class independently. Nothing changed in pre-processing to cause this; it was always like this — the 08-12 run just quantified it.

9×Recorded failure modes

F Nine ways the reader silently fails
F1substituteSingle digit/character swaps inside intact tables — FL 502.57 for the printed 528.57.
F2dropWhole rows dropped — sheet 03: 25 of 28 plat notes; the missing note 27 is the filing's only parkland-credit claim.
F3omit★Whole blocks missing while block-manifest.json declares them valid; sheet 04 transcribed to nothing.
F4shiftSpanning table headers collapsed into a data column — every row shifts one cell.
F5mis-assignSemantic mis-assignment — stall length filed as width; floor elevations mixed into building dims.
F6confabulate★Invented recorded-instrument numbers that resolve to real documents on unrelated properties; invented utility crossings.
F7"correct"Silently fixes the drawing's own errors — a legend transposition quietly repaired, hiding a real filing defect.
F8meaningNon-text meaning lost — checkbox fill, X-outs through voided details, watermark identity, prime vs double-prime.
F9diverge★Two transcriptions of the same printed block disagree with each other and the page — defeats reconciliation checks (sheets 08/09/56, 19–20).

The deeper problemExtraction is near-null on civil sheets

outlined vector, no text layer Most civil sheets are outlined vector with no embedded text: pdftotext got 1,831 chars from sheet 05 vs 31,410 via OCR, and a package-wide search for "watershed" returned zero hits — including the sheet that states it in full. One embedded font dropped every digit 8 from extraction on a sheet that renders fine. The lesson for v2: extraction is not a ground-truth source either — the rendered image is.

Why it stays invisibleEvery AI step is a swallow-path

On failure the pipeline marks the row processed anyway, with NULL/empty fields — so a garbled read is indistinguishable from a genuinely blank sheet.

Summary fails → looks complete
  • Sheet ends processed with NULL summary/label.
  • A garbled PDF yields an unnamed sheet that looks fine.
Transcription fails → empty, silently
  • Sheet ends processed with zero content_block rows.
  • Empty blocks.md reads as a genuinely blank sheet.
Rasterize partial → sheets vanish
  • Page count is derived from rendered .jpgs.
  • A partial pdftoppm truncates the set — no cross-check.
Similarity script errors → mislabel
  • Non-zero exit drops the pair with no log.
  • Matching then mislabels a modified sheet as added.

The tellReview already stopped trusting it

the review side has already demoted the layer The review runbook's own conventions state the vector PDF is the authority, and "a negative reached only by searching text is not a negative." The 08-12 Austin review effectively operated without the transcription layer — re-reading the actual drawings. So today we pay full Gemini cost to generate content our own reviewers already don't trust. That is what makes the v2 move near-inevitable rather than speculative.
evidence: preprocessing-packet/preprocessing-transcription-handoff.md · design-notes.md §1 · exploration-upload-pipeline.md §6

how it kills the modes — independent contexts kill confabulation-convergence (F6/F9); coverage confessions kill silent-missing-sheet (F3); disagreement-as-gap kills silent substitution (F1/F7). The cost leverTiering — the triad isn't free at 57–100 sheets

Two Opus reads + a reconcile per sheet, with zoom crops, across a full civil set is a very different bill from today's ~95-second zero-token script — and it's subscription drain. So reading effort is tiered by how much transcribable content a sheet actually carries. The tier is a cost optimization, not a fidelity compromise: run-1 reads everything with the full triad and measures whether the cheaper drawing-only path loses any defect before we trust it at full-set scale.

Callout-bearing "drawing" sheets (R.O.W. widths drawn as linework on 08/09/18) are exactly why the classifier is generous and the operator has the final say.

The overlayTwo Deltas the plain triad misses

Agreement is not confidence. The four verified defect classes surfaced two gaps the disagreement-as-gap rule can't close on its own — both cheap to design against now.

Delta A — normalization convergence. Two "helpful" readers share the LLM prior regularize the document, so both silently fix PRINCIPIAL, both drop a leading "NO", both dedupe a double-numbered list — and agree. The gap ledger stays empty; the finding is destroyed. → a verbatim / anti-normalization reader brief (preserve typos, duplicates, contradictions, negations, XXXX placeholders exactly) + an image-anchored spot check on agreed cells, precisely because agreement is where normalization hides.
Delta B — cross-sheet semantics. A hatch legended on sheet 13 governs fills used on 17/18/19; a single-sheet reader gets false positives both directions. Every single-sheet PDF carries the wrong Title metadata. → derive sheet identity from the rendered title block, never PDF metadata; and either carry a mechanically-collected legend/symbol table or forbid the reader from resolving a hatch to a meaning at all (record the raw symbol, defer meaning to review). Will's call; the run measures it.

The one-linerTwo consumers of the same pre-processing output

Pre-processing's only outputs are DB rows + storage artifacts (tab 01). Two different review pipelines consume them. The old way — the unattended cloud review workflow — re-renders those rows into progressive-reading markdown inside a Vercel Sandbox and lets N cheap agents navigate the text, reaching pixels only through a vision tool. The new way — the operator-run review runbook — reads a pre-staged on-disk workspace where the vector PDF is the authority and the transcriptions are a demoted convenience layer.

the through-line Both paths ultimately trace back to the same pre-processed data — sheet_version.summary / reading_guide, content_block.content, project_facts.content. The difference is trust: the cloud workflow treats the AI transcription as the primary reading surface; the runbook treats it as a hint and re-reads the drawing itself. That demotion is the whole reason the runbook survives the transcription defects catalogued in tab 02 — and it is the review-side "tell" that made the v2 strip (tab 03) near-inevitable.

Section B · the new wayBureau review runbook operator on-disk

Source of truth: bureau/runbooks/review/RUNBOOK.md. An operator-driven Claude Code session — no Inngest, no Sandbox, no Supabase reads. The pre-processed submission is pre-staged on disk (single-sheet vector PDFs + rasters + transcriptions), and the top-level runner spawns phase orchestrators that read those files directly, with the vector PDF as the authority.

how the data gets on disk The runbook does not use project-downloader.ts and never calls Supabase. Staging the plan-set workspace on the local filesystem is a precondition of the run: the operator (or a preparatory step) puts it there and writes its absolute path into ADDENDUM.md at kickoff. In the v2 world (tab 03) that staging is the pre-processing runbook's publish output.

Section C · seeing it in the appWhere the data surfaces — an annotated field map

Both consumers above read the same pre-processing output. Here is that output as a person sees it — the sheet detail view in cityhall. This is a live capture of Wills Pre-Processing V2 Test Project · plan set v1 · sheet 6 (an Austin Water utility-notes sheet). Every field below is boxed in red and mapped to the data model from tab 01. This is exactly the data project-downloader.ts renders to markdown (Section A) and that the runbook reads off disk (Section B).

The full sheet detail view: heading + summary (left), the rasterized sheet with content-block bounding-box overlays (center), and the Content Blocks list — one row per block, each a category badge + description (right).
sheet_version.summary — the AI page overview. Renders into the README sheet-index line and the top of each guide.md.
sheet / sheet_version — stable sheet identity + sheet_number (6 of 25). sheet_version.label carries the AI short title.
plan_set_version — one row per uploaded iteration (v1). Pins which sheet_versions belong to this submission.
sheet_version.thumbnail_storage_path — the rasterized sheet image (n.jpg). What the cloud vision tool fetches on demand.
sheet_version.storage_path — the single-sheet vector PDF artifact. The runbook's authority (§3); the cloud path only reaches it via the vision tool.
content_block.bounding_box — a normalized [ymin,xmin,ymax,xmax]/1000 region drawn over the raster. One box per transcribed block; order = short_id.
content_block.category — the 11-value enum badge (Callout / Table / Form / General Notes / drawing / legend / seal …).
content_block.description — AI keyword-rich text for retrieval. content_block.content holds the verbatim markdown transcription (→ blocks.md; not surfaced in this view).
sheet_version change-chain — previous_sheet_version_id + change_type / change_description / similarity_score. Blank on v1; the AI sheet-comparison call fills these on resubmittal.
the one field the UI hides The Content Blocks list shows each block's category + description, but not content_block.content — the verbatim markdown transcription. That is the exact field the transcription defects (tab 02) live inside, and the field the cloud review agent reads as blocks.md. It is invisible here, which is part of why the rot stayed invisible for so long.
