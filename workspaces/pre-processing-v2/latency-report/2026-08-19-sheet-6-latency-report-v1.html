Why one sheet took an hour

1 · Serial vision reads dominate

166 render/crop cycles, run essentially one-at-a-time. Each cycle is render → encode → vision round-trip (~8–15 s). That alone is ~25–40 min of pure serial I/O. The sheet is a dense, filled-in Austin Water standard form (small-print tables: demand, LUE, meter sizing, dedication deposit, service-connection notes), which invited granular cropping — 73 crops in Phase 3 alone.

2 · The image-API cap forced a whole extra pass (~18 min)

Reader A and Reader B both independently hit a cumulative ~20-image cap mid-read and left the bottom-right ~45% unread. Recovering it required spawning Reader A2 — the single largest phase. This is a tool limitation, not inherent work; logged to tool-bugs.md with the mitigation (budget/pre-stage bounded ≤2000px crops, which A2, the reconciler and the adversary all used successfully).

3 · The sheet was read ~5× on purpose — and it paid off

Full triad (A + B + A2) → Reconciler → Adversary → corrective re-reads. That redundancy is the whole point of the runbook, and here it earned its keep: the adversarial pass caught a dropped safety-critical negation ("REPAIR COUPLINGS ARE NOT ALLOWED"), a fabricated duplicate note masking an off-by-one, and a dropped review block / PE seal. The fidelity is real; the question is the price.

What this does (and doesn't) imply for scale

  • Don't linearly extrapolate. This was a value-bearing sheet read with the full triad and "tie-break up" fidelity. Most of a 45-sheet set is pure-drawing sheets that take a single literal read + coverage confession — far cheaper. The tier classifier exists precisely to avoid paying triad price on every sheet.
  • Sheets parallelize; a single sheet's passes do not. The design fans out across sheets (up to N workers), so 45 sheets is not 45×57 min. The 57 min is the depth of one hard sheet's dependency chain, and that chain is almost entirely serial.
  • The cheapest win is the image cap. Removing the forced A2 pass reclaims ~18 min (~30% of this sheet). Pre-staging bounded crops up front turns the reader passes from "discover-then-crop" into "read a fixed set".
  • The adversarial + correction loop is ~15 min (~27%). Worth it for a value-bearing sheet given what it caught; a candidate to gate by tier (skip full adversarial on pure-drawing sheets).
  • Compute vs. human vs. deterministic: of the ~77 min end-to-end, deterministic publish was 30 s and the human gate ~20 min. The lever is the reading compute, not the plumbing.

Suggested follow-ups (not yet decided)

  • Fix / raise the per-agent image cap, or pre-stage a bounded crop set → eliminate the A2 re-pass.
  • Tier-gate the adversarial pass (full on value-bearing, light/none on pure-drawing).
  • Batch vision reads where the API allows, to attack the serial round-trip cost directly.
  • Instrument the runbook to emit real per-step timings (this report was reconstructed from file mtimes).
