The decisions Will needs to make

A8 · How to keep amend working. (a) Amend hashes only the files a run reads, recommended. (b) Move the intake files out of the version dir. (c) Accept the break.

A1 · Backfill v2.7's history? Recommended: one version per distinct content, plus a commit-to-version lookup, so all 19 v2.7 reviews resolve.

A2 · Semver. Adopt it? Is regrouping or renumbering PATCH or MINOR (Q-A2a)? Start each checklist at 1.0.0 (Q-A2b)? Does a revert get a new version (Q-A2c)?

A3 · Guide files. Store the files and hash the prose, in Storage or in a text column?

A4 · Spec split. M0 in db-schema v2, M1 in review-linkage, M2–M4 in db-source-of-truth?

A5 · Groups. The identity/placement split, the group ID format, and titles without their CC-N: number?

A6 · Provenance. The generated_by block, and whether a published run must have a run uuid.

A7 · Review counting. What should a count answer, and do the rules on the Runs and reviews tab hold?

Versions

The label v2.7-trimmed has named 18 commits' worth of edits. The 19 reviews that ran on it saw 7 different folder states, and D5's one-revision backfill matches none of them (A1).

None of the 19 v2.7 reviews ran on the content D5 would backfill A1

A counter says only that something changed; a semver says how much A2

v1.2
Is this content hash new for the label?yes →revision = max + 1, whatever changed

otherwisenothing written
proposed
Did an item ID leave the checklist (removed, split or merged)?yes →MAJOR · old reviews and answer keys no longer map one-to-one
no ↓
Was an item added, or did what an item checks change (text, condition, location, binding, source, fail status)?yes →MINOR · that item's verdicts are no longer comparable
no ↓

no ↓
otherwiseno bump · the sync writes nothing

The declared version may be bigger than the computed bump, never smaller. Whether regrouping and renumbering are PATCH is Q-A2a.

jurisdictions/austin/completeness-check/v2.7-trimmed/version.yaml (A2, A6)version: 1.4.2 # semver of this checklist's content; the linter checks the bump format: 1 # the file-format version; the sync refuses a major it doesn't know generated_by: # absent for hand edits runbook: intake-prospecting run_id: 3f2a… # runbook_runs.id, the uuid conductor init creates run_name: new-braunfels-2026-10-20 runbook_commit: 9c1e…

The review names it with no DB lookup. 1.4-resolve already reads the version dir. It would copy version into resolved.json, and from there into reviews.metadata.intakeVersion.

The key changes. PK (checklist_id, version) replaces (checklist_id, revision). The sync fails if one version arrives with two hashes, which catches a content change nobody bumped.

Runs and reviews

A review today records a folder label and a commit; intake-prospecting records a run's directory name, not its run uuid. Neither is enough to join reviews to items or to name the run that made an item (A4, A6, A7).
