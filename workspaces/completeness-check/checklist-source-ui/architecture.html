03 · captureSnapshot captureWhich recipe each source gets, how the Requirements page is opened, and the URL-map fixes.

The Requirements page keeps its content in 17 CKEditor accordions with no aria-expanded; as loaded, only about 2,000 of 43,800 characters are visible (§1.3).

Choosing a capture recipe

Label names a whole code (LDC Title 25, DCM)?yes →document_level · link only, nothing captured
no ↓
widen source or a plain .pdf URL?yes →pdf-direct via /content/<id>/pdf/ · body must start %PDF
no ↓
Municode section (LDC, DCM, TCM, UCM)?yes →render chapter · isolate the nodeId chunk · print it (else bureau-text copy)
no ↓
webpage (Requirements page, addressing, TAC)?yes →force-open with CSS · verify ≥ 98 % · one PDF page per panel
no ↓
otherwise, or visible text below 98 %capture fails · names the shortfall

Claim (D8): a webpage capture fails if visible text is under 98 % of the content's raw text, so a half-opened page can never pass as captured.

04 · locate and reviewLocating each item's passageHow a box is made, how a citation ends, and what an override looks like.

A worker picks the first and last word of each region; boxes come from the PDF's own word geometry (D12, §3.8).

How a citation ends

An override exists for this item and label?yes →apply it · rebuild boxes from its quote · no model call
no ↓
Label has no URL, or names a whole code?yes →unresolved_label / document_level
no ↓
Worker finds the passage on the hinted page or panel?yes →found (if the quote checks out)
no ↓
Worker finds it elsewhere in the document?yes →found · page_hint_mismatch
no ↓
otherwise, or the quote is not in the picked wordsnot_found · rationale kept · shown at review

Claim (D13): a find outside the hinted page is kept but flagged, which also surfaces wrong page hints in the guides such as CC-22-25.
