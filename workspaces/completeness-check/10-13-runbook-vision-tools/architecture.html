How vision works in CC runbook runs

How a review worker in 2.1-review asks to look at a sheet or document for one checklist item, which model answers (Gemini through the AI Gateway, the legacy-parity default, or a native claude -p session, the opt-in new way), which file it is shown, and every place the request is logged and traced afterwards. Describes the current code; changes nothing. Companion to DESIGN-SPEC.md.

OverviewThree ways to answer “look at this sheet”

The legacy workflow had an in-process vision tool. The runbook ported it to a command-line tool, bin/vision.ts, that the review agent runs through Bash. The CLI has two modes. gateway (the default) is the old way: the same Gemini model, prompt and inputs. claude is the new way: a one-shot claude -p session that reads the file itself. Both modes write the same log.

Activity flowOne checklist item, from transcription to finding

Each 2.1-review worker owns one guide for one run and must emit exactly one finding per checklist item id. Vision is a fallback the agent reaches for only when the preprocessed transcription is not specific enough.

EOther readers

cc-compare (runbooks/cc-compare, step 2.1-adjudicate) reads the review cells' vision logs to see what each run was told, and may call the same vision CLI itself to settle a disputed item.
Not the vision CLI: 2.12-annotate (comment markings, Opus) reads rendered crops natively to place markers. It renders no verdict, is the one exception to AGENTS.md rule 2, and has its own pixel_reads section in 2.11.

Open questionsWhat the current design leaves open

Q1 The two modes can show a different version of a document. Gateway sends the newest document_version (legacy parity); claude uses the staged PDF, the version the submission links. For a document re-uploaded after the submission they analyze different files.
Q2 Claude-mode spend sits outside conductor's ledger. Only 2.11 totals it, at list price.
Q3 Attribution is self-reported. --item-ids is whatever the agent typed (missing only warns), and IG's line-to-call join is a timestamp + prompt-prefix heuristic. Two cells were unreconciled on WWCW_rb2_run2_claude_vision.
Q4 tools_used is not cross-checked against the log, so a finding can claim or omit vision without a matching line.
Q5 Gateway mode logs no usage. Tokens and cost per call are only in the AI Gateway dashboard, by run id and node tag.
Q6 The tile grid is copied into IG's slicer and must be kept in step with vision.ts by hand.
