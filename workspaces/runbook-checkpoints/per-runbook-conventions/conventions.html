RUNBOOK CHECKPOINTS · PER-RUNBOOK CONVENTIONS

Each runbook chooses its conventions; the run declares its answer posture

Today every conductor2 run gets all 21 AGENTS-core rules, and the only override available is to contradict one. This proposal splits the core into fragments each runbook opts into (option A), and replaces rule 19's single bar with a posture declared per runbook and inherited strictest-wins down the run chain (option C). Companion to DESIGN-SPEC.md.

!Where the core already contradicts a runbook's job

preprocessing-v4 · rule 19

Rule 19 bars "the jurisdiction's own review comments on this case", and in the same sentence says every document the applicant filed is in bounds. Valley View's MCR is both. Across four runs the reader read / refused / read / withheld it. A refusal fails the ≥50%-verbatim contract and parks the run.

anchor-geometry · rule 19

It fits frames "to the SIR's county parcel" (runbook.yaml:3). Rule 19 names "a previous … SIR" as barred prior Noetic output about the property. So far the model has resolved this tie in the runbook's favour.

process-city-response-docs · rule 19 (at port)

Its whole job is to turn the city's MCR and redlines into CRC guides. It's a prose RUNBOOK.md today, so it doesn't get the core yet. It will contradict rule 19 on the day it moves to conductor2.

smoke, geometry, PPv4 · rules 2–6, 8, 9, 13, 15, 21

GIS magnitude checks, headed-vs-headless browsing, sampling strata, and "regulations, never laws" land on test fixtures and plat readers that never go near them. They're noise at best.

the wrinkle The bar is a property of the run, not of the runbook. site-research runs inside review and inside sir and must be barred in both. guide-training runs inside prospector. conductor already solves this shape for the OS sandbox: sandbox_enabled() reads the outermost run's runbook.yaml (mod.rs:239-262).

✕Alternatives not chosen

B · one template, omit:/replace:

Finest control, but it's a small patch language. Nobody can read a runbook's effective rules without assembling them, and a replace: goes stale silently when the core rule under it changes.

C alone · posture only

Fixes rule 19, which is the important half, so it's kept. But the other 19 rules stay on every runbook.

D · no shared core, plus a consistency test

The most honest assembled file, but ten copies of the craft rules. A test catches drift but not a forgotten update.

Data fix only

Necessary, not sufficient. anchor-geometry's contradiction with the SIR isn't a data problem, and PPv4's reader would still have a tie to break.
