Agent rules: before and after

Today one rulebook, AGENTS-core.md, is put in front of every agent in every runbook. After this change each runbook picks which parts of it apply, and declares whether its agents may read "the answers". Companion to DESIGN-SPEC.md.

Draft v1.1 · 2026-09-28 · two tabs ↓

Before · todayOne rulebook for every runbook

Two kinds of rule file sit in bureau. When a run starts, conductor copies them into the run folder, glues them into one AGENTS.md at the run's root, and every agent in the run reads that file.

3What's inside AGENTS-core.md: four kinds of rule in one file

KindIn plain wordsWho it's really for
How to work (9 rules)use scripts for math, count back delegated work, log tool bugs, don't invent results, finish in the sessioneveryone
How to research (9 rules)check GIS numbers, prove a "none found", cite what you actually readresearch runbooks (SIR, review, site-research, prospector)
Client wording (1 rule)"regulations" not "laws"; no internal jargonclient deliverables (SIR, review)
Don't read the answers (rules 19–20)no earlier Noetic output on this project, and no city review comments on this caseruns we measure accuracy on (review, SIR, site-research)
the problem Every runbook gets all four kinds. The only way a runbook can get out of a rule is to contradict it in its own AGENTS.md, and then the agent has to pick which one to follow. That's how the PPv4 reader ended up reading the Valley View MCR on some runs and refusing it on others. anchor-geometry reads the SIR, which rule 19 forbids. process-city-response-docs, whose job is reading city comments, will hit the same wall once it moves to conductor.

After · proposedEach runbook picks its rules

The same four kinds of rule, now in separate files. Each runbook says in two lines of runbook.yaml which it wants. The trip into the run is the same as today; conductor just picks files before gluing.

1The files, in the bureau repo

Goes away
lib/AGENTS-core.md
Comes in
lib/conventions/ craft.md how to work (always) sourcing.md how to research (opt in) client-register.md client wording (opt in) answers-barred.md don't read the answers answers-prior-output.md don't read earlier Noetic output; city docs are fine
each runbook.yaml gains two lines · e.g. preprocessing-v4conventions: [] # which opt-in files: sourcing, client-register answers: prior-output # barred | prior-output | open (left out = today's rules)

Each runbook's own AGENTS.md stays as it is, minus the "where we disagree, this file wins" line.
