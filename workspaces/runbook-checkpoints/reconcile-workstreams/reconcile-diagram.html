Section 1One feature, built twice — A merged, B open

The runbook control plane / HITL got implemented in parallel by two people. A (Jason, substation#247) merged to main on 2026-09-09; B (mine — #245/#1549/#663) is still open. They are mostly complementary; the genuine overlap is small but real — and on a collision course.

AJason · #247 · merged

The cloud spine, machine-to-machine. Two tables runs + gates, four routes, a per-run HMAC bearer, ajv schema validation, a full test suite.

  • Launch · callback · reconcile (dry-run stub) · decide.
  • No UI, no local lane, no checkpoint stream.
  • RLS enabled but no policies; realtime off — left as "Will's call".

BMine · #245/#1549/#663 · open

The human surface + local lane. Three tables runbook_run + runbook_checkpoint + runbook_hitl_question, one answer route, a bureau captain CLI, a cityhall console.

  • Checkpoint stream drives the UI; live RLS + realtime.
  • Local captain lane + in-session answering; real user attribution.
  • Cloud driver deferred — the answer route only flips the run to queued.

Section 4Path forward — converge on A, graft B

A is merged, has the harder cloud plumbing + tests, and is the design of record. B's surface is additive. So: keep runs+gates, add a checkpoints table, extend the decide route, re-target B's local lane + UI.

1The converged model

Data

  • Keep runs + gates; add checkpoints (B's stream).
  • gates.kind += clarification.
  • Add gates.decided_by_user_id (→auth.users) + channel.
  • Turn RLS policies + realtime ON (B's noetic-member SELECT).
  • Keep A's gates.schema+ajv; drop B's zod registry.
  • Adopt A's enums (parked/done, open/decided); drop B's run_dir.

Routes

  • Keep A's launch / callback / reconcile.
  • Extend POST /api/gates/:id/decide: noetic-JWT, channel, clarification-parks.
  • Retire B's /runbook-hitl-questions/:id/answer.
  • Reconcile effectful body still unbuilt (run-env workstream).
